# Habez AI — Phase 3.1: AI Agent внутри Habez Pro

**PHASE 3.1: COMPLETED** — 26 сентября 2026.

Первый рабочий помощник по товарам Habez. Он отвечает только на данных
слоя знаний (Evidence Model) и карточек, показывает источник у каждого
утверждения, раскрывает расхождения, не выбирает «победителя» в споре и
ничего не пишет в базу.

Статус был PARTIAL только из-за ручной проверки входа в панель. Теперь
вход, права, интерфейс и выход проверяются автоматически: сквозными тестами
API с настоящим входом и сценарием в браузере (раздел «Проверки»).
Настоящие пароли для этого не нужны.

## Контракт: слои и их интерфейсы

```
request     { tenantId, scope, question, history }          routes.js → runAgent()
  → intent     detectIntent(q) → compare|packaging|spec|recommend|overview|search
  → retrieval  detectProducts(q, catalog) · unknownNames(q, corpus) · callTool(name, args, { tenantId, scope })
  → evidence   get_product_specs / compare_products → свойства с наблюдениями и строками карточки
  → conflicts  single | agreed | conflict | unresolved (+ вопросы сверки D1–D10)
  → context    buildContext(…) → { text с [E#], evidence[], properties[], variants[] }
  → LLM        provider.stream({ system, messages, maxTokens, signal, hints })
  → validation checkAnswer(answer, evidence, { question, forbidden })
  → stream     SSE: start → meta → delta… → done | error
```

| Слой | Модуль | Вход → выход |
|---|---|---|
| HTTP, права, лимиты, журнал | `agent/routes.js`, `agent/permissions.js` | запрос → роль (`public`/`staff`/`admin`) → поток SSE |
| намерение | `retrieval/intent.js` | вопрос → intent, `specFilter` (ключи характеристик), слова поиска |
| товары | `retrieval/entities.js` | вопрос + каталог → товары (с падежами); неизвестные имена |
| инструменты | `tools/index.js` | `callTool(name, args, ctx)`: проверка схемой zod, права по `ctx.scope` |
| споры | `retrieval/conflicts.js` | строки карточки или наблюдения → свойства «ключ × условие × фасовка» со статусом |
| контекст | `runtime/context.js` | свойства → текст с номерами `[E#]` + реестр ссылок |
| модель | `provider/` | `stream()` / `generate()`; `messages.js` — Messages API через fetch, `mock.js` — без сети |
| проверка ответа | `runtime/context.js → checkAnswer` | ответ + реестр → `grounding` |
| конвейер | `runtime/agent.js → runAgent` | всё выше + время по этапам (`timings`) |

События потока: `start {conversationId, requestId}`, `meta {intent, scope,
products, found, unknown, conflicts, evidenceCount}`, `delta {text}`, `done
{citations, grounding, withheld, model, latencyMs, timings, stopReason,
truncated}`, `error {message}`.

Беседа на сервере не хранится. История (до 10 реплик и
`AI_HISTORY_MAX_CHARS` знаков) приходит с каждым вопросом. В браузере она
лежит в `sessionStorage` вкладки: ключ свой у каждого пользователя, при
выходе все беседы стираются. Таблиц для бесед нет.

## Инструменты (только чтение)

| Инструмент | Что | Права | В конвейере |
|---|---|---|---|
| `search_products` | товары по словам вопроса, строки «Область применения» | все; только опубликованные | подбор и поиск |
| `get_product` | карточка, разделы, фасовки | гостю — только опубликованные | всегда при названном товаре |
| `get_product_specs` | свойства со статусом спора | гость — строки витрины; сотрудник — наблюдения **и** строки карточки, которых в наблюдениях нет; без конфиденциального; админ — всё | вопросы о товаре |
| `compare_products` | свойства 2–4 товаров | как `get_product_specs` | сравнение |
| `get_product_evidence` | наблюдения с происхождением | сотрудник и выше; гостю — `forbidden` | нет (для вызова моделью в Phase 3.2+) |
| `search_knowledge` | наблюдения по словам | сотрудник и выше; гостю — пусто | нет (для вызова моделью в Phase 3.2+) |

Инструментов записи нет. Каждый проверен тестом: права трёх ролей,
отсутствие запрещённых наблюдений, пустой результат, «ни одной записи в
базу» (`total_changes()` не меняется).

Сотрудник видит **не меньше** покупателя. Раньше строки карточки вне
словаря («Заливка наливных полов — через 7 суток») и второе значение,
отброшенное переносом 2.1 («50 циклов» при «F50»), сотруднику не
показывались. Теперь показываются. Значение карточки по спорному свойству
встаёт в ту же строку и получает тот же статус спора. Проверено тестом по
всем товарам тестовой базы и отдельно на копии рабочей: потерь 0.

## Споры

| Случай | Поведение |
|---|---|
| одно значение | используется |
| несколько согласных | значение и все источники |
| расходятся | `conflict`: все значения, победителя нет |
| по ключу открыт вопрос сверки (D1–D10) | `unresolved`: все значения + номер вопроса |
| разные условия (7 / 28 сут, «на мешок») | разные свойства, не спор |
| разные фасовки | не смешиваются |
| разные единицы | не пересчитываются: «единицы разные, НЕ пересчитывать» (и при `conflict`, и при `unresolved`) |
| история удалённых значений (40 шт. на поддоне, `generated_default`) | в контекст модели не идёт |
| товар, которого нет в каталоге («ГИПСОМАКС-900») | модель не вызывается: «товара нет, данных нет» |
| нет данных по характеристике | в контексте явная пометка «данных нет» |

Автотесты по каждому случаю из задачи: Стандарт 0,5 / ≥0,6 → unresolved
(D1); ШОВ 0,5 / ≥0,3 (7 сут) → unresolved (D4); ШОВ 2 / ≥2,5 → unresolved
(D2); ШОВ 60 / 70 мин → unresolved (D3, D6); АНТИПЛЕСЕНЬ 90–100 мл/м² /
200 г/м² → unresolved (D5), без пересчёта; ГКЛ 9,5 / 12,5 мм — отдельные
строки; 7 / 28 суток — не спор; КОРОЕД 5–7 л → `water_per_bag`, `per=bag`,
фасовка «мешок», связь с `water_ratio` — вопрос D10.

## Проверка ответа (validator)

`checkAnswer(answer, evidence, { question, forbidden })` → `grounding`:

| Поле | Ловит |
|---|---|
| `invalidCitations` | ссылка на номер, которого нет в реестре **этого** ответа (в том числе номер из прошлого ответа; история уходит модели без номеров) |
| `unsupported` | число с единицей, которого нет ни в одной строке данных |
| `mismatched` | число есть в данных, но не в тех строках, на которые ссылается эта строка ответа: смешаны фасовки, условия, товары |
| `uncited` | число с единицей без ссылки, которое нигде в ответе не стоит рядом со своей ссылкой |
| `echoed` | число из вопроса, которого нет в данных, повторено, чтобы его опровергнуть («5 МПа в данных нет») — не ошибка |
| `forbidden` | значение или документ, которые роли не положены (гостю — всё из наблюдений, сотруднику — конфиденциальное) |

`grounded = true`, только если нет ошибок пяти видов: несуществующих ссылок
и `unsupported`, `mismatched`, `uncited`, `forbidden`.
Если в ответе оказались недоступные роли данные, в `done` приходит
`withheld: true`: интерфейс заменяет текст предупреждением и не показывает
источники. `unsupported` и `mismatched` интерфейс показывает
предупреждением под ответом, `uncited` — мягкой подсказкой.

## Доступ

| Роль | Уровень | Что видит |
|---|---|---|
| гость, покупатель, дилер | public | карточку витрины; только факт «есть внутренние вопросы сверки» |
| менеджер | staff | витрина + public и internal наблюдения, вопросы сверки, происхождение; про конфиденциальное — только факт |
| администратор, владелец | admin | + конфиденциальное |

Гостю и покупателю агент доступен только при `AI_AGENT_PUBLIC=1`, иначе
401 и 403. Наблюдения уровня `public` гостю пока не показываются: его канал
— карточка витрины.

Если в запросе есть токен, но сервер его не принял (истёк, подделан,
учётная запись заблокирована), ответ — **401 `session_expired`**. Раньше
такой запрос молча получал права гостя. Интерфейс в этом случае обновляет
вход, а если не получилось, пишет «Сессия истекла — войдите заново».

## Защита от расходов

- вопросов за окно — на человека: вошедшего считаем по учётной записи,
  гостя — по адресу; 60 / 12 за 10 минут; превышение — 429;
- одновременных ответов — 2 на человека, дальше 429 «Дождитесь ответа»;
- гостям и покупателям вместе — 300 ответов в сутки, дальше 429 «задайте
  вопрос менеджеру»; сотрудников этот предел не касается;
- вопрос до 2000 знаков, история — до 20 реплик; длинная реплика
  обрезается, а не отклоняется, модели уходит не больше
  `AI_HISTORY_MAX_CHARS`;
- «Стоп» и закрытая вкладка обрывают запрос к модели. Проверено на
  поддельном сервере: соединение закрыто, новых кусков нет. На настоящем
  OpenRouter поток обрывается за 6 мс после «Стоп», кусков после него 0;
- нет данных или выдуманный товар — модель не вызывается вовсе.

## Журнал

`ai agent answer`: номер беседы и запроса, роль, уровень, намерение, число
источников, споров и ссылок, итог проверки (`grounded`, число
`unsupported`/`mismatched`/`uncited`/`invalidCitations`/`forbidden`,
`withheld`), модель, время по этапам, токены, успех.
**Не пишется**: вопрос, ответ, значения, ключи, личные данные. Прерванный
ответ пишется как `aborted`.
