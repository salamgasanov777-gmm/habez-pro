# Habez AI — Phase 3.3: Product Intelligence Agent

**PHASE 3.3: COMPLETED** — 26 сентября 2026, ветка `feat/habez-ai-3-3`, коммиты `7f6e9d4…` (4 шт., в GitHub не отправлены).

Phase 3.2 научила Habez AI находить и объяснять данные. Phase 3.3 учит
решать практические задачи вокруг продукции Habez. Помощник:
- рассказывает о товаре паспортом;
- подбирает товары под задачу;
- объясняет, почему товар подходит или нет;
- сравнивает товары применительно к задаче;
- говорит, как применять — только по данным завода.

По-прежнему только чтение: товары, характеристики, цены, склад, заказы,
источники, проверки и сверка не меняются.

```
вопрос → задача (сценарий) → данные товаров → доказательства, условия, фасовки
       → правила пригодности → объяснение → ответ со ссылками
```

## Устройство

Новых таблиц нет. Product Intelligence — производный слой над слоем знаний
и моделью наблюдений (`api/src/ai/agent/intel/`):

| Модуль | Что делает |
|---|---|
| `usecases.js` | 12 сценариев применения: задача пользователя → канонический сценарий, у каждого разделы-кандидаты, группы признаков, данные «против», важные характеристики |
| `suitability.js` | пригодность товара для сценария: пять состояний, правилами, по видимым роли данным; проверка «подходит» вопреки статусу |
| `select.js` | подбор: кандидаты → пригодность → группы по статусу; порядок — каталожный, не рейтинг |
| `profile.js` | паспорт товара, извлечение инструкции по применению, совместимость |
| `run.js` | пути конвейера: паспорт, подбор, пригодность, применение, совместимость, сравнение по задаче |

Детерминированная часть (поиск товаров, характеристики, кандидаты,
статусы, условия) работает до модели. Модель получает готовую структуру и
только объясняет её, статусы ей менять нельзя. Для «недостаточно данных» и
«совместимость неизвестна» модель не вызывается вовсе.

АНТИПЛЕСЕНЬ?» — вопрос о характеристике, а не подбор «от плесени».
Основание задачей считается: ГКЛ в «швах ГКЛ» — основание, а не кандидат.

## Пригодность

| Состояние | Когда |
|---|---|
| `SUPPORTED` | выполнены все группы признаков |
| `PARTIALLY_SUPPORTED` | выполнена часть групп |
| `NOT_SUPPORTED` | явное «НЕТ» по признаку сценария |
| `INSUFFICIENT_DATA` | нет признаков ни за, ни против |
| `CONFLICTED` | спор по нужному признаку или «за» и «против» одной группы |

`INSUFFICIENT_DATA` не превращается в `NOT_SUPPORTED`, частичное — в
подтверждённое. Объяснение каждого результата: товар, статус, основания
со ссылками [E#], данные против, расхождения, чего не хватает, причина.

Пример на рабочих данных, «Что использовать для швов ГКЛ?»:
- **ШОВ** — подтверждено: назначение «заделка стыков ПГП и ГКЛ» и
  «основание ГКЛ: ДА»;
- **ФИНИШ** — частично: основание ГКЛ есть, о швах не сказано;
- **Синдика, Старт, Синдика-МН, Старт-МН** — не подходит: прямо указано
  «швы ГКЛ — НЕТ»;
- **остальные** — данных недостаточно.

## Права

Пригодность считается только по видимым роли значениям:
- **гость** — по карточке витрины;
- **сотрудник** — без конфиденциального;
- **администратор** — по всем данным.

Проверено тестом: конфиденциальный замер «ШОВ — для фасада ДА» против
карточки «НЕТ» даёт «не подходит» гостю и сотруднику и «данные
противоречат» администратору. Ссылка на документ замера в контекст не
попадает.

## Режимы ответа

| Режим | Когда |
|---|---|
| `PRODUCT_PROFILE` | «Расскажи про ШОВ», «Для чего ШОВ?», «Что у ГКЛ 12,5 мм?» — паспорт по разделам: назначение, основные свойства (до 14), условия, применимость ДА / НЕТ, фасовки, коды, расхождения, пробелы, упоминаемые товары, источники |
| `PRODUCT_SELECTION` | «Что использовать для швов ГКЛ?», «Подходит ли ШОВ для фасада?», «Почему?» |
| `PRODUCT_APPLICATION` | «Как применять КОРОЕД?», «Какая вода нужна…», «Какой слой нанесения указан?» — раздел карточки и значения отдельно, чего нет — названо |
| `COMPARISON` | по задаче — ещё пригодность каждого товара и «выбор зависит от…», победителя нет |
| `CONFLICT`, `FACT`, `NOT_FOUND`, `CLARIFICATION` | как в 3.2 |
| `INSUFFICIENT_DATA` | пригодность или совместимость подтвердить нечем — ответ без модели |

## Применение и совместимость

- Инструкция собирается из разделов карточки и структурированных значений:
  подготовка, приготовление, вода, нанесение, слой, время, условия, расход,
  хранение, безопасность. Если по вопросу о применении числа нет, но
  карточка говорит об этом словами («толщина наносимого слоя соответствует
  размеру зерна»), это ответ, а не «нет данных».
- «5–7 л на мешок» не превращается в «на 25 кг». В подсказке модели прямо
  сказано: в цитату раздела ничего не дописывать, фасовку называть отдельно
  со своей ссылкой. Проверка ответа ловит такую приписку как «число не из
  указанного источника».
- Совместимость — только прямое упоминание. Карточка ШОВ называет грунтовку
  «Эконом» — это `STATED` со ссылкой. Иначе `UNKNOWN`, а не «совместимы».
  Материалы-основания (лист, плита) — не совместимые товары: для них есть
  ключи «основание …: ДА / НЕТ».

## Многоходовой подбор

| Реплика | Понимается как |
|---|---|
| Что использовать для швов ГКЛ? | подбор; текущий товар — первый подтверждённый (ШОВ) |
| Почему? | пригодность ШОВ для той же задачи |
| А если нужна фасовка 25 кг? | тот же подбор + отметка фасовки у каждого кандидата |
| А что у Стандарта? | пригодность Стандарта для той же задачи → «данных недостаточно» |
| Сравни ШОВ и Стандарт для ГКЛ → Какой из них лучше? | сравнение по задаче, без победителя |

Задача хранится в состоянии беседы (`current_use_case`).
