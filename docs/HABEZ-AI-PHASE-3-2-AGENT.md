## Конвейер одного ответа

```
вопрос + состояние беседы + refBase
  → маршрут (retrieval/router.js)
      намерение, товары (retrieval/resolver.js), характеристики и условия
      (retrieval/specs.js), отсылки «у него», «их», «А у Стандарта?»,
      ответ на уточнение («12,5 мм»)
  → решения без модели
      товара нет → NOT_FOUND; неясно, какой товар или фасовка, или «по трём
      характеристикам» без перечня → CLARIFICATION
  → план (runtime/plan.js): инструменты чтения по маршруту
      get_product / get_product_specs / compare_products / search_products /
      search_knowledge
  → отбор: характеристики (в т. ч. строки карточки по подписи), условия,
      фасовка, история удалённых значений
  → режим: FACT | COMPARISON | CONFLICT (+ NOT_FOUND, если спрошенного нет)
  → пакет доказательств с номерами [E#] (runtime/bundle.js)
  → модель с инструментами (runtime/agent.js + runtime/tool-runner.js)
      данных хватает — отвечает; не хватает — вызывает инструмент, результат
      дописывается в пакет со следующими номерами, ещё ход
  → проверка ответа (runtime/context.js → checkAnswer)
  → поток SSE: start, status, meta, delta, reset, done
```

### Цикл инструментов: ограничения

| Ограничение | По умолчанию | Переменная |
|---|---|---|
| вызовов инструментов моделью на ответ | 8 | `AI_AGENT_MAX_TOOL_CALLS` |
| ходов модели (последний — без вызовов, `tool_choice: none`) | 3 | `AI_AGENT_MAX_TURNS` |
| записей в пакете доказательств | 160 | `AI_AGENT_MAX_EVIDENCE` |
| знаков контекста | 48 000 | `AI_AGENT_MAX_CONTEXT_CHARS` |
| общее время на ответ | 120 с | `AI_AGENT_TOTAL_TIMEOUT_MS` |

Одинаковый вызов (то же имя и аргументы) второй раз не выполняется. При
исчерпании лимита модель получает «ответь по имеющимся данным». «Стоп» и
общий таймаут прекращают и поток модели, и цикл. Текст хода, после которого
модель вызвала инструмент, с экрана убирается (событие `reset`). Вызов
инструмента использует встроенный вызов Messages API: поток `tool_use`,
его поддерживает вход OpenRouter; проверено на настоящей модели.

## Маршрутизатор

`routeQuestion(q, { catalog, state })` → например:

```json
{ "intent": "comparison", "products": ["ШОВ", "СТАНДАРТ"], "specs": { "keys": ["adhesion_strength"], "ambiguous": null },
  "conditions": {}, "productsFrom": "question" }
```

Намерения: `product_lookup`, `spec_lookup`, `comparison`, `application`,
`packaging`, `condition`, `source`, `conflict`, `unknown`. Правилами, без
модели.

## Поиск товаров (resolver)

| Ранг | Как | Пример |
|---|---|---|
| 100 | точное имя, короткое имя, имя в кавычках | ШОВ, ГКЛО |
| 90 | с падежным окончанием | ШОВа, ШОВом, стандарта, АНТИПЛЕСЕНЬЮ |
| 70 | опечатка (Дамерау — Левенштейн ≤ 1, для длинных ≤ 2; от 5 букв) | стандрат, корроед |
| 50 | слова названия | «пазогребневая полнотелая влагостойкая» |
| 40 | предметное слово: один товар — он, несколько — уточнение | «гипсокартон» → «ГКЛ, ГКЛВ, ГКЛО или ГКЛВО?»; «огнестойкий гипсокартон» → ГКЛО |

Имя-обычное слово («ФАСАД», «ФИНИШ») называет товар только вместе с видом
(«краска ФАСАД») или заглавными. Марка «Хабез» товар не называет. Товар,
которого нет в каталоге («ГИПСОМАКС-900»), модель не получает вовсе.
Понятия заглавными (GTIN, NTIN, ГОСТ) — не товары.

## Характеристики, условия, фасовки

- «прочность сцепления» → `adhesion_strength`; «на сжатие» →
  `compressive_strength(_28d)`; «изгиб» → `flexural_strength`; «время
  схватывания» → `setting_time` + `setting_time_start` (D3/D6); «расход
  воды» → `water_per_bag` / `water_ratio` / `water_mix_ratio`; «листов на
  поддоне» → `per_pallet`; GTIN / NTIN.
- **Голое «прочность» — группа, помеченная как неоднозначная.** Агент
  показывает каждый вид отдельно и не выбирает адгезию сам.
- Строки карточки без ключа словаря («Прочность на растяжение при изгибе в
  возрасте 7 сут») находятся по подписи.
- Условия: «через 28 суток» отбрасывает значения на 7 суток. Они
  называются только как «данные есть для других условий». Значение без
  указанного возраста остаётся с пометкой «условие в источнике не
  указано». «На мешок» → `per=bag`; «при толщине 1 мм» → `layer_mm=1`;
  ключ `…_28d` = 28 суток.
- Фасовка: «12,5 мм» → только эта фасовка. Строки карточки, где названа
  другая («63 шт (9,5 мм) / 51 шт (12,5 мм)», «GTIN, 9,5 мм»), отбрасываются.
  Если фасовка не названа, а значения разные — уточнение с кнопками. Если
  значение одно — используется.

## Состояние беседы

Не данные товаров, а «о чём сейчас речь»: `current_product`,
`current_products`, `current_variant`, `current_spec`, `current_specs`,
`current_condition`, `last_intent`, `awaiting`. Сервер проверяет его схемой
(лишние поля — 400) и возвращает новое в `done.state`. Хранит браузер
вместе с беседой; при выходе стирается. В базу не пишется.

| Реплика | Понимается как |
|---|---|
| Расскажи про ШОВ | товар ШОВ |
| А какая у него прочность? | ШОВ (из беседы), прочность — все виды |
| А у Стандарта? | Стандарт, та же характеристика |
| Сравни их | сравнение ШОВ и Стандарта по прочности |
| А какая у него прочность? (после сравнения) | уточнение: «О каком товаре речь: ШОВ или СТАНДАРТ?» |
| Сколько листов ГКЛ на поддоне? → 12,5 мм | уточнение фасовки → ответ для 12,5 мм |

## Пакет доказательств

Каждая запись: `claim, value, raw_value, unit, product, variant, packaging,
condition, assertion_type, source, source_type, source_date, verification,
access_level, status, conflict_id` (+ строка свойства для проверки). Номера
сквозные в беседе: клиент присылает `refBase`, сервер возвращает `refNext`.
Номер из прошлого сообщения в новом ответе недействителен.

## Споры и доступ

Правила 3.1 сохранены: одно значение — ответ; согласные — одно значение и
все источники; разные — спор; разные условия и фасовки — не спор; единицы не
пересчитываются; замена — только из модели наблюдений; «победителя» нет.

Если скрытые данные (internal/confidential) расходятся с витриной по тому же
свойству и условию:

- **гость и покупатель** видят «в системе есть дополнительные внутренние
  данные, поэтому окончательное значение не опубликовано», без значения;
- **сотрудник** видит то же про конфиденциальное: «скрытое значение»;
- **администратор** видит весь спор.

## Сравнение

`compare_products` возвращает таблицу: строка — характеристика (ключ ×
условие), ячейка — значения и статус по каждому товару или «нет данных».
Сначала общие строки. В окне чата — таблица в своей прокрутке, номера в
ячейках ведут к источникам этого сообщения.

## Проверка ответа (усилена)

Сверх 3.1:
- число сверяется вместе с единицей: «5 МПа» при «0,5 МПа» — выдумка,
  «0,5 кг» при «0,5 МПа» — не из источника;
- **чужой товар** — товар, которого нет ни в данных ответа, ни в их тексте;
- участники спора и пометки контекста («другие условия: 7 сут») считаются
  данными;
- число из прошлого ответа беседы — не ошибка, а мягкая пометка «не
  перепроверено»: историю присылает браузер, доказательством она не
  считается;
- готовые ответы сервера (уточнение, «нет данных») не проверяются как
  ответы модели.
