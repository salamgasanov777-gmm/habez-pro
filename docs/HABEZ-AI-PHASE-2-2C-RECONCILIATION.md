## 1. Происхождение 726 старых записей

### Как устанавливалось

1. **Звено «карточка Habez Pro → ai_product_specs».** Для каждой записи в
   текущей карточке ищется ровно та строка, из которой её перенесли: тот же
   вид (ярлык / таблица), тот же заголовок таблицы, тот же ключ словаря и
   то же значение (`legacy-provenance.js`). Найдена — `product_card`. Не
   найдена — `unknown_legacy_origin`.
2. **Звено «приложение №1 → карточка Habez Pro».** Значение строки
   прослеживается по 22 версиям `products.json` приложения №1 до коммита, в
   котором оно появилось. Коммит отнесён к виду источника по его
   сообщению. Исходный каталог 31.08 (`e4ddf47`) источника не записал, поэтому
   его значения — `unknown`.

## 2. Проверка права на публикацию

Правило (`publicationDecision`): public + не догадка + проверено человеком
+ действует + источники согласны.

| | Записей |
|---|---:|
| Удовлетворяют всем условиям сейчас | **0** |
| В плане 2.2B получили бы `public` при переносе | 726 |
| После исправления переноса получают `public` | **0**: все `internal` до решения D9 |
| Блокер при переносе | `access_level_not_public`: 726 |
| Блокер, даже если бы доступ был `public` | `not_verified`: 726 |
| Происхождение выше карточки неизвестно | 654 — перенос даёт им `product_card` (строка в карточке доказана), но подтверждать ли их «по карточке» без заводского документа — решение D8 |
| Видны на витрине уже сейчас (строка в опубликованной карточке) | 726 — витрина читает карточки, а не AI-слой |

Правка кода: `legacyObservationInput()` ставит всем перенесённым `internal`.
Вид источника доказывается строкой карточки. Проверка переносится только
для видов, которые можно подтвердить.

### D. Обязательные случаи

**ШОВ, 0,5 и 0,3 МПа**

| Вопрос | Ответ |
|---|---|
| Одна характеристика? | По смыслу да: прочность сцепления = прочность на отрыв. Новая подпись «…в возрасте 7 сут» словарём не сопоставлена |
| Одно условие? | **Нет.** У 0,5 возраста нет, у 0,3 — «в возрасте 7 сут» |
| Одна единица? | Да, MPa. Признак границы разный: точное значение против «не менее» |
| Замена доказана? | Слова «0,3 МПа вместо 0,5» есть только в сообщении коммита `1e43732` — это вторичная запись. Документа технолога на диске нет |
| Есть ли доказательство источника? | Строка таблицы в №1 после `1e43732` — перепечатка документа технолога |
| Что не решено | Связывать ли как замену: D4. По правилу R8 без решения замена невозможна: условие разное |

**ШОВ, 60 и 70 минут** — ключи разные: `setting_time` («Время схватывания»)
и `setting_time_start` («Начало схватывания»). Единица та же, условий нет.
«70 вместо 60» — только в сообщении коммита. Что это одно свойство, не
доказано. Решения D3 и D6.

**ШОВ, 2 и не менее 2,5 МПа** — та же величина и единица. Условие разное
(без возраста и 7 сут). О замене в записи ничего не сказано. Решение D2.

**АНТИПЛЕСЕНЬ, 90–100 мл/м² и 200 г/м²** — ключ тот же. Единицы разные:
объём и масса, пересчёт не делается. «Вместо» есть в сообщении коммита
`b4866a5`. На этикетке (`4f97b6e`) записано «около 200 грамм на 1 м²». В
самом №1 ярлык до сих пор 90–100 мл/м², а таблица — 200 г/м². По правилу
R8 замена возможна только решением (D5). Сейчас это конфликт
`different_units`.

**СТАНДАРТ, 0,5 и не менее 0,6 МПа**

| Вопрос | Ответ |
|---|---|
| Разные источники? | **Нет.** Обе строки появились одним коммитом `e4ddf47` (исходный каталог 31.08). Один документ противоречит сам себе |
| Разные документы? | Нет, один и тот же неизвестный |
| Заявление или норма? | Обе — нижние границы: у ярлыка «не менее» в подписи, у таблицы — в значении. Ни одна не помечена как норма ГОСТ или замер |
| Одинаковый тип утверждения? | Да. Разнести их по declared и norm значило бы выдумать тип утверждения |
| Хранить обе без конфликта? | Хранить обе — да, как два наблюдения. Но итог по-прежнему «ждёт решения»: заявленный минимум у завода один. Логически «≥0,6» не противоречит «≥0,5» |
| Что видит покупатель | **Обе цифры** на одной карточке (проверено в браузере) |
| Что отдаёт старый API | 0,6 МПа. Перенос берёт таблицу вместо ярлыка — это правило кода, **не утверждённая истина** |

**ГКЛ, 9,5 и 12,5 мм** — в `ai_product_specs` толщина хранится одной
строкой на товар: «9,5 мм / 12,5 мм». Это текст, значения не смешаны
числом, но и не разнесены. В `variants` фасовки отдельные: 47/48 (ГКЛ),
49/50 (ГКЛВ). В модели наблюдений `per_pallet`, `gtin`, `ntin` бывают
только у фасовки, а замена между фасовками «по словам источника»
запрещена (тесты).

**7 и 28 суток** — в старом слое возраст зашит в ключ
(`compressive_strength_28d` у КОМПОЗИТа, Стяжки, ТЕПЛОКОМа) или стоит только
в подписи, и тогда строка не сопоставлена (ШОВ). Двух значений одного
ключа с разным возрастом нет. В наблюдениях возраст — условие `age_days` с
цитатой.

**КОРОЕД, 5–7 л на 1 мешок** — в старом слое основание «на мешок»
потеряно: 5–7 л в единице l, хотя нормализатор ждёт l/kg. В наблюдениях —
условие `per=bag` с цитатой «на 1 мешок». К фасовке 25 кг не привязано
(в тексте её нет), в л/кг не пересчитано (тест).

## 6. seed.js

**Было** (`api/src/db/seed.js`, стр. 128):
`per_pallet: pack.unit === "кг" && pack.size >= 25 ? 40 : null`. В исходных
данных сида (`legacy-products.json`) количества на поддоне нет: 27
упоминаний — только «хранить на поддонах».

**Стало** — `per_pallet: null` с пояснением. Это правка кода, данные она не
трогает:

- новые базы (`npm run seed`, `reset`, тестовые) больше не получают «40»;
- неизвестное количество остаётся `NULL`, витрина строку «На паллете» не
  показывает;
- сид не создаёт наблюдений. Если «40» когда-нибудь попадёт в слой знаний,
  то только как `generated_default`: такое наблюдение не подтверждается и
  не публикуется (тесты).

**Не лечит** уже заполненную рабочую базу: 29 значений остаются до решения
D7. Выгрузка на сервер (`export-catalog` → `import-catalog`) перенесёт их
как есть.

## 8. Правила замены

Связь `replaces` с основанием «по словам источника»
(`explicit_source_statement`) создаётся, только если одновременно:

1. та же характеристика (`spec_key`);
2. та же фасовка;
3. то же условие (`condition_key`);
4. та же единица, если обе известны;
5. есть цитата или ссылка на документ.

Во всех остальных случаях — только `user_decision`, то есть решение
владельца. Правило в `addRelation()`, проверено тестами.

Проверка случаев по этим правилам:

| Случай | Ключ | Условие | Единица | «По словам источника» возможно? |
|---|---|---|---|---|
