### Production — только GitHub Pages

| | |
|---|---|
| Production | https://salamgasanov777-gmm.github.io/habez-pro/ — ветка `gh-pages`, папка `/`. Единственный действующий production |
| Release command | `./deploy.sh` (без цен) — **только** этим скриптом |

| Backup | внутри `./deploy.sh` → iCloud Drive, «Habez Gips — копии базы/hgz-ГГГГ-ММ-ДД_ЧЧ-ММ.db» + `vapid.json`, хранятся 30 последних |
| Rollback | **автоматического нет.** Откат — повторная выкладка ранее выбранного коммита с соответствующей копией базы. Версию и копию выбирает владелец |

**Требования рабочего процесса** (выполняет Release Manager / главный чат,
сам скрипт их не проверяет). Выкладка разрешена только:
- из ветки `main`;
- из чистой рабочей папки (`git status` пустой);
- после успешных тестов (`npm --prefix api test`);
- после успешных сборок (`build` и `build:standalone`);
- после показанного и проверенного плана выкладки (RELEASE / DEPLOY PLAN);
- после отдельного подтверждения владельца на эту выкладку;
- в базе нет демо-цен (после `npm run reset` / `seed:demo` не выкладывать).

После выкладки: smoke; проверить, что появилась копия базы с временем этой
выкладки; изменённый `web/public/data/catalog.json` без решения владельца
не коммитить (репозиторий публичный).

**Текущее поведение скрипта `./deploy.sh`** (как есть, не исправлено):
1. `scripts/backup-db.sh` — копия `api/var/hgz.db`; если копия не сделалась,
   выкладка **продолжается**.
2. `node api/src/db/export-static.js [--with-prices]` — каталог из базы
   (`DATABASE_FILE`, иначе `api/var/hgz.db`) в `web/public/data/catalog.json`.
3. `npm --prefix web run build:standalone` → `web/dist-standalone/`.
4. В `web/dist-standalone/`: `rm -rf .git`, `git init`, один коммит
   «Выкладка <дата>», `git push -qf … gh-pages` — **force push**: история
   `gh-pages` каждый раз заменяется одним коммитом, прошлая версия с GitHub
   пропадает.
5. Скрипт **не проверяет** ветку, чистоту рабочей папки, тесты, сборку и успех
   копии; собирает то, что лежит в папке сейчас, включая незакоммиченное;
   с какого коммита собрано — нигде не записывает.
6. Повтор допустим: результат зависит только от кода и базы; каждый запуск —
   новая копия и полная замена `gh-pages`.

```bash

```

## Уведомления менеджерам

Новый заказ и заявка уходят push-уведомлением в приложение на телефон
менеджера (карточка «Уведомления о заказах» в сводке панели). Ключи VAPID
создаются сами при первом запуске и лежат в `api/var/vapid.json` — входят
в копию базы. Telegram — дополнительный канал, включается переменными
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, пока не настроен.

На айфоне push работает только у каталога, установленного иконкой.
Заработает по-настоящему после переезда на хостинг: с компьютера владельца
менеджеры до сервера не дотянутся.

## Правила, которые нельзя нарушать

1. **Цены и остатки не выдумывать.** Настоящих у нас нет. `npm run seed` ставит
   всем товарам «цена по запросу». Демо-цены — только `npm run seed:demo`,
   и на публичный сайт они попадать не должны. `./deploy.sh` без флага
   цены и остатки вырезает. **`./deploy.sh --prices` публикует цены из
   текущей базы как есть — демо-цены тоже**: скрипт не отличает их от
   настоящих. Этот режим — только с подтверждёнными ценами завода, после
   проверки данных в базе и отдельного подтверждения владельца.
2. **Приложение №1 не трогать.** Ни файлы в `~/Desktop/HGZ_app`, ни репозиторий
   `hgz-catalog`, ни его сайт.
3. **Телефон отдела продаж — 8 (928) 032-75-21** (перенесён из приложения №1
   12 сентября 2026, стоит в подвале). **WhatsApp на этом номере нет** —
   владелец подтвердил 12 сентября. Настройка `whatsapp` остаётся пустой,
   заявки с сайта собираются в готовый текст. Не спрашивать повторно.
4. **Ключи, домены и договоры оформляет завод.** ЮKassa, SMS, хостинг —
   до кнопки «оплатить» доводим код, дальше учётные записи владельца.
5. Владелец — не программист. Объяснять обычными словами, команды давать
   целиком, готовыми к копированию. Если можешь сделать сам — делай сам,
   не выдавай список ручных шагов.

## Решения, которые легко случайно откатить

- **Шторка товара на телефоне не меняет адрес.** Открывается через
  `state.sheet` в записи истории, адрес остаётся адресом каталога (как в
  приложении №1). Иначе жест «назад» от края листает «снимки» экранов.
  Переходы из шторки — `replace`. Прямая ссылка `/p/…` — обычная страница.
- **Первый экран** — плитки подбора по задаче и лента «Новое в каталоге»
  (`newArrivals` считает сервер: добавлено после первого дня и не старше
  месяца). Синий блок с цифрами убран по решению владельца 12 сентября.
- **Порядок товаров** выставлен по приложению №1 (`products.position`).
- Сортировка каталога на телефоне скрыта, на компьютере есть.
- В окне QR-кода только код и кнопка «Скопировать ссылку», адреса текстом нет.
- **Сроки и даты в SQL сравнивать только через `julianday()`**:
  `julianday(expires_at) > julianday('now')`, не `expires_at > datetime('now')`.
  JS пишет ISO с буквой T (`toISOString()`), SQLite — с пробелом; строковое
  сравнение в пределах суток всегда даёт «ещё не истекло». Так было с
  сессиями и кодами входа до 26 сентября 2026, тест —
  `api/test/security-expiry.test.js`. Относится к любым новым срокам
  (корзина, скидки, акции, ссылки).
